# 鸿蒙 7 复赛版更新说明

## 2026-10-28 更新：内置模型服务

应用自带一个模型服务，不用配置就能提问。全部改动位于 `harmony-app`，另有密钥写入脚本和测试。

### 内置服务

- **首次打开即可提问**：使用随应用打包的 DeepSeek（`deepseek-v4-flash`）。「我的」里新增「内置服务 / 自定义」切换：
  - 内置服务显示状态、模型和「今日可用 N / 100 次」；
  - 自定义就是原来的配置表单，切换时不会清掉已填的内容；
  - 已经配置过自己密钥的用户，升级后仍停在「自定义」。
- **每日次数**：
  - 每台设备每天 100 次，0 点恢复；
  - 普法、维权对话、卷宗报告、合同 AI 审查共用，合同 AI 审查一次只计 1 次；
  - 请求在拿到回答前失败时，不计这次；
  - 两次请求至少间隔 2 秒；
  - 本地法规检索和合同规则审查不消耗次数。
- **次数用完时**：提示卡出现在提问处，提供「去『我的』」（填自己的密钥）和「只看法条」。「只看法条」不调用模型，直接列出本地检索到的条文和依据编号，并注明未经模型分析。
- **隐私说明**：根据当前模式，写明内容发送到应用提供的服务，还是用户配置的服务。

### 密钥的存放

- **生成方式**：运行 `tools/harmony/builtin-service/set.sh`，在不回显的提示中输入密钥，脚本写入 `rawfile/builtin_service.json`。
  - 文件已加入 `.gitignore`；
  - 没有这个文件时，应用照常构建，只提供自定义模式；
  - 脚本会去掉粘贴时混入的方向键、首尾空白等字符，仍有异常字符时拒绝写入。
- **安全限度**：文件里的密钥经过编码，安装包里搜不到明文，但解包仍能还原。因此应使用专门为应用创建的密钥，只充少量余额并开启消费提醒，不再需要时作废。
- **混淆**：发布构建的 ArkGuard 混淆仍未开启。开启属性混淆会影响法规库等 JSON 数据的解析，需要先补保留规则。

### 其他

- **普法首页的错误提示**：移到输入框下方。原来在页面底部，会被标签栏挡住。

### 真机验证记录（HarmonyOS 7，API 26）

- **假密钥 + 每日次数临时设为 0 的测试版本**（不调用模型）：
  - 已有自己密钥时仍停在「自定义」；切到内置服务后显示 100 / 100，重启后仍保留选择；
  - 次数用完时提示卡出现在输入框下方；「只看法条」列出条文，问题滚到顶部；
  - 切回「自定义」后原配置完好；
  - 去掉密钥文件后只剩自定义表单，安装包里不含该文件。
- **真实密钥**：首次写入时混入了方向键字符，导致认证失败，脚本已增加清理；清理后内置服务回答正常。
- **未在真机验证**：次数从 100 逐次扣减到用完的完整过程。
- **测试**：逻辑测试 42 项、合同规则 57 个用例全部通过。

- **普法、维权 · 梳理、合同报告用同一套规则**：

- **可阅读区域**：维权对话的回答区由约 58% 增加到约 88%。
- **不会误触发**：
  - 发送后自动滚动、跳到最新等程序滚动不会触发收起；

### 合同体检

- **导入**：DOCX、PDF（没有文字层的页面用手机文字识别）、TXT，或证据库里识别为「合同」的照片。
- **补充事实**：合同签了吗、工作城市（从卷宗带入）、岗位、是否接触商业秘密；合同期限和试用期从正文自动识别，可修改。
- **本地规则审查**：移植自桌面版 `contract_review`（结构审计、R001–R018），并做了以下修正：
  - 三年合同的试用期上限按 6 个月计算（原实现按 2 个月）；
  - 期限和试用期从正文读取；
  - 风险挂到规则命中的条款上；
  - 复述「不得收取押金」等禁止性规定不再误报；
  - 识别全角数字、「百分之N」、以「个月」计的竞业期限；
  - 每条结论只等它依赖的事实；
  - 修正 R007、R008 的法条引用。
- **新增规则**：R019 婚育限制、R020 罚款、R021 加班费按最低工资计算、R022 社保按最低基数、R023 工资低于当地最低工资；「旷工视为自动离职」降为待确认。
- **最低工资数据**：整理自 m12333.cn（2026-09-16 发布，非官方网站），只有省级分档：低于全省最低档报红线，介于各档之间标待确认。
- **AI 审查**（可选，用户自己配置的模型）：
  - 每批 6 个条款，最后做一次全文反向推演和漏项检查；
  - 只能引用检索到的法条编号（K1、K2…），挂错条款的意见剔除并重问，最多 2 次；
  - 没有依据的「无效」降为待确认，规则结论优先于 AI 意见；
  - 发送前替换姓名、身份证号、手机号、住址、银行卡号，可预览要发送的内容。
- **结果**：
  - 总览按严重程度排列，并按合同签没签标注「签了也无效」「签前要求修改」等；
  - 条款对读显示原文、理由、可打开原文的依据、建议和证据缺口；
  - 底部输入框可带着审查结果到维权里继续问；
  - 报告保存在本机。

## 2026-10-26 更新

本次更新三项：普法对话界面改版、展示模型思考过程、桌面卡片摇一摇后自动返回并加入振动。全部改动位于 `harmony-app`。

### 普法对话界面

- **输入框固定在底部**：进入对话后，输入框悬浮在导航栏上方，只有对话内容滚动，往上翻阅长回答时也能随时追问。弹出键盘时导航栏隐藏，输入框贴在键盘上方。本地法规检索状态缩成框内的书本图标，免责提示缩成框下一行小字。还没开始对话时，首页的大输入卡片和常见问题不变。
- **发送后问题停在顶部**：新问题滚到对话区顶部，回答在它下面流式生成，不再自动把视图拉到底部。生成过程中发送键变成停止键。
- **回到最新**：最新内容在下方超过一定距离时，右下角出现 ↓ 按钮，点击滚到底部。
- **回答去掉卡片**：助手回答不再放在卡片里，左侧头像也去掉了，文字直接排在页面背景上、占满整行；字号和行距略微放大。用户问题保留气泡。
- **依据卡片收成按钮**：每轮回答下方的「本轮检索依据」卡片改为按钮行里的「依据 N 条」，点开仍是全部依据弹窗，法规库提示保留在弹窗中。按钮放不下时自动换行。案件页和报告页保持原样。

### 模型思考过程

- **解析**：支持 `reasoning_content`（DeepSeek、通义千问等推理模型）、`reasoning` 字段，以及正文里的 `<think>` 标签；标签被拆到两个数据块里也能正确识别。
- **展示**：生成时显示「正在思考 · N 秒」并实时展开思考内容，正文开始后收成「已思考 N 秒」标签，可以再次展开。保存的思考内容最多 8000 字。
- **不回传**：思考内容不会在后续轮次发回模型（DeepSeek 会拒绝包含历史 `reasoning_content` 的请求）。
- **设置**：「思考过程」卡片可以关闭展示，或选择生成时自动展开。

### 桌面卡片

- **自动返回**：摇一摇进入维权小贴士后，约 8 秒自动回到四入口，贴士里提示「稍后自动返回四入口」。如果卡片进程被系统回收、定时器没触发，下次卡片重新显示时会补上返回。8 秒内连续摇两次，以最后一次为准。
- **振动**：天平展开时同步振动：起始一下轻触，中间一段渐强细振，天平落定时一下重击。设备不支持自定义节奏时，改为首尾两次系统预设振动。新增 `ohos.permission.VIBRATE` 权限。振动受系统触感反馈开关控制，开关关闭时系统会直接忽略。

## 2026-10-23 更新

本次新增「证据库」，形成「拍照 → 变清晰 → 识别 → 入库 → 检索 → 进卷宗」的完整证据链，同时支持复制回答。全部改动位于 `harmony-app`。识别、增强、索引和信息提取都在手机端完成，图片和识别文字不会上传。

### 回答复制

- **复制和复制含依据**：每条回答下方有「复制」和「复制含依据」两个按钮。前者只复制正文；后者把引用标签还原成 `[依据n]`，并在文末附上实际引用到的依据清单和免责声明。卷宗报告也支持。
- **长按选择**：回答长按后可以拖动金色手柄调整选区。系统菜单里的「复制」被接管为纯正文复制，另外新增「复制含依据」，只附上选区里用到的依据。用户自己的问题气泡也支持长按选择。
- **防误触**：选择文字期间，普法页的右滑打开抽屉会暂停。

### 证据库（案件页入口）

- **导入**：支持两种方式。
  - 扫描纸质材料：Vision Kit 文档扫描控件，自动矫正，一次最多 10 张；
  - 从相册选择：系统安全图库，应用只能访问用户选中的图片，一次最多 9 张。
- **处理流程**：每张图片依次经过四步：保存到本机 → 图像超分 → 文字识别 → 建立检索索引。Core Vision Kit 不支持同一能力并发调用，所以所有图片排队处理，详情页显示每一步的进度。

### 图像超分（鸿蒙 7 新增 `imageSuperResolution`）

- **触发条件**：长宽都小于 2048px、短边小于 1080px 的低清图片会自动超分，比如被压缩过的微信截图。其他图片显示跳过原因；符合尺寸限制的图片也可以手动点「增强清晰度」。
- **两遍识别**：超分后对增强图和原图各识别一次，详情页可以切换对比两份结果。
- **对比滑块**：拖动分隔线对比超分前后；「放大 3×」以分隔线为中心放大，便于看清数字的差别。
- **实测结果**：
  - 540×750 的模糊工资条超分为 2160×3000（放大 4 倍）。
  - 原图把「1,500.00」识别成「1.500.00」，增强后识别正确，项目名和数值也按行对应上了。
  - 但增强后漏识别了「绩效奖金」中的「绩」字，所以两份结果都保留。

### 检索（鸿蒙 7 新增 `textSearchImage` 文搜图）

- **两路检索**：
  - 文字检索：在识别文字里查找关键词，配有证据类别同义词，比如「考勤」同时查「打卡、出勤」；
  - 语义检索：用文搜图按画面内容找图。
  - 两路结果合并排序，每条结果都标明「文字命中」或「画面相似」，并高亮命中的那一行文字。
- **实测结论**：
  - 搜「截图」只返回 4 张手机截图，没有误把文档类材料算进来；
  - 搜「聊天」能找到识别文字里没有「聊天」二字的聊天截图；
  - 按内容查询（工资条、打卡记录）主要靠文字检索。
  - 文搜图服务会按每次查询自动设置约 0.31–0.34 的相似度门槛，只返回门槛以上的结果。
- **索引维护**：删除材料或重新超分时会同步更新索引；清空本机记录时一并清空索引；遇到错误码 `1013100003`（检索能力已更新）时自动清空并重建索引。

### 分类、信息提取与卷宗联动

- **自动分类**：材料自动分为工资、合同、考勤、聊天、解除通知、社保、其他七类。每个类别要求出现只有原件才会有的锚点词，比如合同必须有「甲方」或「乙方」，避免把只是提到合同的 AI 回答截图归为合同。聊天截图的文字缺少特征，改用文搜图查询「聊天记录」来补充判断。用户可以手动修改类别，手动选择的类别不会被自动覆盖。
- **按行重组**：利用识别结果中每行文字的坐标，把同一行的项目名和数值配对，比如「应发合计 8,500.00元」。
- **信息提取**：从材料中提取单位名称、平均月薪、案件发生地和时间节点，每条都标明来源。月薪取「应发」，因为经济补偿按应得工资计算。日期和地点在规则提取不到时，用 Natural Language Kit 的实体识别兜底。
- **填入卷宗**：用户点「填入」后才会写入卷宗；卷宗中已有不同的值时，先弹窗确认是否替换。识别结果可能有误，所以不会自动覆盖。
- **带着材料问 AI**：把识别出的文字作为附件放进案件对话，沿用现有的防提示注入规则。
- **对照证据库**：解析 AI 回答中的「证据清单」，逐条核对证据库。类别对上的显示「已有」，只是文字里提到的显示「可能相关」，都没有的显示「缺少 · 去导入」；点任意一条可以直接跳到证据库对应的类别或检索结果。
- **卷宗报告**：生成报告时附上按类别汇总的已有证据清单。

### 其他

- 证据库是独立组件 `components/EvidenceLibrary.ets`，没有继续增加 `Index.ets` 的代码量。
- 新增服务：`EvidenceStore`、`EvidencePipeline`、`EvidenceIndex`、`EvidenceSearch`、`EvidenceExtractor`。其中检索合并和分类提取都是纯函数，已用 Node 单独测试。
- Core Vision Kit 只在中国境内可用，并且不支持模拟器；超分和文搜图需要 API 26 及以上。低版本系统会隐藏超分和画面检索，只保留文字检索。

## 2026-10-22 更新

本次更新集中在稳定性、聊天记录和法条引用体验，全部改动位于 `harmony-app`。

### 稳定性与性能

- **本地检索移到后台线程**：52MB 法规索引的解析和每次提问的检索都放到常驻 Worker（`workers/KnowledgeWorker.ets`）中完成，界面线程只负责读取文件并把数据整块交给 Worker，不做复制。检索打分规则保持不变，结果与之前一致。
- **检索提速**：每份文档的小写标题、规范化标题、地区等字段改为加载时计算一次。此前每次查询都要对 5 万多个文本块重复执行正则规范化。
- **流式回答**：普法咨询、案件梳理和卷宗报告改为边生成边显示（SSE），并提供「停止生成」，已生成的内容会保留。服务若不支持流式、直接返回普通 JSON，同样能正常处理。

### 聊天记录

- **对话与卷宗本机保存**：普法对话、案件对话、卷宗六项内容和分析报告保存到应用沙箱（`ChatStateStore.ets`）。应用被系统回收后重新打开会自动恢复。写入经过临时文件再替换，避免中途崩溃留下损坏的文件。
- **历史咨询侧边抽屉**：普法页每轮问答结束后自动归档，最多保留 50 段，每段保留最近 100 条消息。抽屉按「今天 / 昨天 / 近 7 天 / 更早」分组，支持搜索、左滑删除，并高亮当前对话。
- **打开方式**：点击标题栏菜单按钮，或在普法页上从左向右滑动打开。屏幕最边缘留给系统返回手势，所以页面上任意位置右滑都可以拉出抽屉；关闭可以点遮罩、向左拖动或用系统返回。
- **标题栏按钮**：菜单按钮和返回首页按钮在标题栏展开时位于金色短线下方，收起后移到标题左侧，位置随滚动平滑过渡。
- **对话时间**：只有发送新消息才更新对话时间。切换对话或返回首页不再改动时间和排序。
- **清空记录**：设置页新增「本机记录」卡片，可确认后清空全部对话、历史与卷宗。

### 法条引用

- **可点击的引用标签**：回答中的 `[K1]` 显示为金色数字标签，点击后从底部弹出法条卡片。卡片包含法规名称、条号、效力状态（现行有效 / 已失效 / 尚未生效 / 已被修订 / 未标注）、施行日期、条文原文和来源文件，可左右切换其他依据。
- **高亮被引用的句子**：卡片会尽量在原文中高亮被引用的那句话。模型改写措辞导致找不到相同片段时，只显示原文、不高亮。
- **适用范围**：普法回答、案件回答、正在生成的回答、卷宗报告以及历史对话都可以点击。从报告中打开的法条卡片关闭后会回到报告。

### 视觉与主题

- **光感效果**：抽屉使用毛玻璃底加 HDS 点光源（`hdsEffect.pointLight`）。手指在抽屉上滑动时，金色光晕跟随手指移动，交互方式与悬浮导航栏一致。
- **组件材质说明**：测试设备（HarmonyOS 7.0.0.109）报告支持 `ImmersiveMaterial`，但组件级 `systemMaterial` 渲染为透明，因此抽屉没有采用组件材质。底部面板仍使用系统材质。
- **主题切换时图标同步变色**：通用图标组件改为按引用传参。此前 `@Builder` 按值传参，图标颜色会停留在应用启动时的主题，浅色模式下部分图标显示为黑色。
- **浅色模式图标底色**：「先把情况告诉我」和「本地法规库」的图标在浅色模式下改为浅色底。
