# 参赛材料素材：劳动法律 AI 智能体

供后续制作参赛 PPT、演示视频、答辩稿使用。内容来自当前代码（提交 8ada167）和开发过程中的真机验证记录（详见 `docs/contest/harmonyos7-release-notes.md`）。标注「待确认」的地方需要团队核实后再用于正式材料。

## 1. 名称与定位

- **应用名称**：劳动法律 AI 智能体（2026-11-09 定名）。
  - 桌面图标名、应用内标题、桌面卡片、系统设置和分享面板里都用这个名字；手机桌面图标下显示为「劳动法律 AI 智…」。图标图案不变。
- **包名**：`com.laborlaw.aiassistant`，版本 1.0.0。
- **一句话定位**：面向普通劳动者的 HarmonyOS 原生劳动法律 AI 助手——从普法咨询、整理证据到审查合同，帮劳动者在自己的手机上把维权需要的事情理清楚。
- **来历**：由团队原有的 Python 劳动法 AI 演示项目（桌面版）演进而来，用 ArkTS/ArkUI 重写为鸿蒙原生应用。

## 2. 要解决的问题

以下是我们在开发中针对的具体难点。社会层面的数据（如劳动争议案件数量）尚未整理，待确认后补充，不要直接引用未核实的数字。

- **看不懂法律**：遇到欠薪、辞退、未签合同、加班费等问题，普通人不知道适用哪条法律，网上的答案来源不明、无法核对。
- **说不清案情**：维权需要地点、单位、工资、时间节点、诉求、经过等要素，当事人往往只会口头描述，缺少结构化整理。
- **证据零散**：工资条、考勤截图、聊天记录、合同照片散落在相册和聊天应用里，难以查找、分类和提取关键信息。
- **合同风险看不出**：签合同时识别不了「工资已含加班费」「自愿放弃社保」「试用期超长」等违法或高风险条款。
- **隐私顾虑**：合同、工资、聊天记录高度敏感，不愿意上传到第三方服务器。

## 3. 目标用户

- **核心用户**：普通劳动者和求职者，尤其是遇到欠薪、被辞退、加班费争议、未签劳动合同、社保问题的人。
- **使用场景**：
  - 签合同前：拍下或导入合同做体检；
  - 发生纠纷时：咨询法律问题、梳理案情、整理证据，生成分析报告后再去找律师或劳动仲裁；
  - 平板上整理和查看材料，手机上随时拍照取证。
- 待确认：是否有面向特定人群（如新就业形态劳动者、外来务工人员）的定位或调研数据。

## 4. 核心功能与用户价值

| 板块 | 功能 | 用户价值 |
| --- | --- | --- |
| 普法 | 多轮问答，回答流式生成；每个引用显示为可点的角标，点开看法条原文、效力状态、施行日期和来源文件；历史咨询本机保存（最多 50 段），可搜索 | 答案有据可查，不是只看 AI 一面之词 |
| 维权 · 梳理 | 像聊天一样描述经过，AI 分析问题并追问缺失信息 | 不懂法律术语也能把案情说清楚 |
| 维权 · 卷宗 | 六项要素（案件发生地、单位名称、平均月薪、时间节点、核心诉求、详细经过），完整度达到 60% 可生成结构化分析报告（事实摘要、待确认信息、初步风险、证据建议、行动步骤） | 把口头描述变成可以交给律师或仲裁的材料 |
| 维权 · 证据 | 文档扫描或相册导入；本机图像超分、文字识别、自动分为七类（工资、合同、考勤、聊天、解除通知、社保、其他）；文字和画面两路检索；从材料中提取单位、月薪、地点、时间，一键填入卷宗；对照分析报告里的证据清单，标出已有、可能相关和缺少 | 证据集中管理、可搜索，关键信息不用手抄 |
| 合同体检 | 导入 DOCX、PDF（含扫描件）、TXT 或证据库里的合同照片；本机规则审查（规则编号 R001–R023）；可选 AI 深度审查；在原文上标注风险，点标红处看理由、依据、建议和可改写条款 | 签字前看出风险条款，并知道依据在哪 |
| 我的 | 内置模型服务（每天 100 次）或自定义 OpenAI 兼容服务；外观、光感强度；本机记录管理；新手引导 | 开箱即用，也可以接入自己的模型 |
| 桌面卡片 | 欠薪、未签合同、违法解除、加班四个入口；摇一摇展开天平动效并振动 | 不进应用也能快速开始咨询 |
| 维权材料闪控窗 | 跨应用悬浮显示六项材料的完成状态 | 在聊天或相册里找证据时，随时知道还缺什么 |
| 手机 → 平板 | 碰一碰或华为分享，把证据从手机发到平板证据库 | 手机取证，平板整理 |

## 5. 技术亮点

### 鸿蒙特性的运用

**HarmonyOS 7 沉浸光感**
- `HdsTabs` 悬浮页签，「我的」为 mini bar，使用系统沉浸材质。
- `HdsNavigation` 标题栏：页面顶部显示品牌蓝色渐变和天平，滑动后切换为系统沉浸玻璃（`IMMERSIVE_GRADIENT_BLUR`）。
- 弹窗、提示、开关使用系统材质。
- 「我的 → 光感强度」可选自适应、强、均衡、弱，作用于页签。

**鸿蒙 7 新增能力**
- `imageSuperResolution` 图像超分：低清证据图先变清晰再识别，并保留原图和增强后两份结果对比。
- `textSearchImage` 文搜图：按画面内容检索证据，例如能找到文字中没有「聊天」二字的聊天截图。

**AI 与视觉能力**
- Core Vision Kit 文字识别。
- Vision Kit 文档扫描控件。
- Natural Language Kit 实体识别：规则提取不到日期和地点时兜底。

**多设备协同**
- 碰一碰（Share Kit `knockShare` 发送，`dataReceive` 沙箱接收）：手机碰平板，证据直接进入平板证据库，并在碰的位置显示接收动效。
- 华为分享：本应用注册为图片分享目标，从图库或聊天应用分享图片即可存入证据库。

**平板适配**
- 按窗口宽度分三档：手机、平板、平板横屏。
- 平板横屏时左右分栏：
  - 普法：历史咨询常驻左栏；
  - 维权：梳理与卷宗、证据并排；
  - 合同：原文与问题详情并排。
- 平板上整体放大（`setCustomDensity`）。

**其他系统能力**
- Form Kit 桌面服务卡片，`LiveFormExtensionAbility` 互动卡片（摇一摇）。
- 悬浮窗（`FLOAT_VIEW`，受限 ACL 权限）：维权材料闪控窗。
- Asset Store Kit：本机安全保存用户自己的 API Key，禁止跨设备同步。

### 工程实现

- **本地法规检索**：法规索引随安装包发布（约 52MB），在常驻 Worker 中解析和检索，不卡界面，不联网。
- **可核对的引用**：模型只能引用检索到的条文编号；不存在的引用会被校验剔除。
- **合同 AI 审查的约束**：
  - 每批 6 个条款，最后做一次全文反向推演；
  - 依据挂错条款时剔除并重问，最多 2 次；
  - 没有依据的「无效」结论降为待确认；
  - 规则结论优先于 AI 意见。
- **流式回答与思考过程**：边生成边显示，可以停止；推理模型的思考过程单独展示，不回传给模型。
- **引导式演示**：「张三的维权故事」分五步，填入示例后由演示者发送，实时调用模型；模型 5 秒无输出时可改用事先真实调用录制的备用结果，并明确标注。
- **测试**：纯逻辑部分用 Node 单独测试，包括检索合并、分类提取、配额、文本处理等，共 45 项；合同规则有 57 个用例。

## 6. 关键设计决策及原因

| 决策 | 原因 |
| --- | --- |
| 法规检索、证据识别和分类、合同规则审查都在本机完成 | 合同、工资、聊天记录高度敏感；本机处理不依赖网络，也不需要自建服务器 |
| 不自建后台，模型由应用直连（内置服务或用户自己的服务） | 不保存任何用户数据，降低隐私风险和运维成本 |
| 回答必须附法条依据，角标可点开原文 | 法律问题容错率低，用户需要能自己核对；模型改写措辞时只显示原文、不硬高亮 |
| 发给模型前替换合同中的姓名、身份证号、手机号、住址、银行卡号，并可预览发送内容 | 让用户知道并控制什么离开了手机 |
| 规则审查优先于 AI，AI 结论没有依据就降级 | 避免模型「编造」无效条款；规则结果可复现、可测试 |
| 从证据提取的信息需要用户点「填入」才写入卷宗，不自动覆盖 | 识别可能出错，最终由用户确认 |
| 内置服务每天 100 次、两次请求至少间隔 2 秒，用完可切换「只看法条」 | 控制内置服务成本；超额时仍能用本地法规检索 |
| 标题栏在页面顶部用品牌渐变，滑动后交给系统沉浸玻璃 | 兼顾品牌识别和鸿蒙 7 系统材质。曾试过全程蓝色玻璃，但深蓝半透明压在白色内容上会发灰，也不跟随系统光感档位，因此放弃 |
| 普法、维权滚动时保留页签，只有轻点才进入沉浸阅读 | 突出悬浮页签；避免滚动时控件忽隐忽现 |
| 平板横屏分栏，而不是简单放大 | 手机上需要来回切换的页面（对话和卷宗、原文和问题详情），在平板上同屏显示 |
| 碰一碰和华为分享并存 | 碰一碰只在部分设备组合上可用：MatePad MRO-W00 不支持手机碰平板，WKI-W00 支持；华为分享所有设备都能用 |
| 演示模式使用独立数据目录，退出即清除 | 演示时不污染、也不暴露用户自己的真实案件 |
| 演示的备用结果必须来自真实调用 | 现场网络不稳时演示不卡死，同时不冒充实时调用 |

## 7. 可验证的数据与成果

以下数据都可以在当前代码或真机上复现。

**本地法规库**
- 资料 2794 份，其中 2765 份可检索（手机「本地法规库」卡片显示）。
- 离线索引含 52903 个文本块。这是扩充到 2794 份之前的统计，待确认当前数量。
- 资料为机械收录，尚未完成全面法律效力审查。

**测试**
- 逻辑测试 45 项全部通过：`tools/harmony/logic-tests/run.sh`。
- 合同规则 57 个用例全部通过：`tools/harmony/contract-rules/run.sh`。

**合同规则**
- 代码中的规则编号为 R001–R023，其中没有 R004（待确认原因）。
- 移植自桌面版时修正了若干问题，例如三年期合同的试用期上限原实现按 2 个月计算，现改为 6 个月。
- 最低工资数据整理自 m12333.cn（非官方网站，2026-09-16 发布），只有省级分档。

**真机验证**
- 测试设备：HUAWEI Mate 60 Pro（ALN-AL00）、MatePad Pro（MRO-W00）、MatePad（WKI-W00），均为 HarmonyOS 7，API 26。
- 合同体检：
  - 示例合同本地规则审查查出 17 处问题，其中红线 8 处；
  - 开启 AI 深度审查后共 24 处（2026-11-05 一次真实调用的结果，每次可能不同）。
- 证据：
  - 540×750 的模糊工资条超分到 2160×3000；
  - 原图把「1,500.00」误识别为「1.500.00」，增强后识别正确。
- 碰一碰：ALN-AL00 碰 WKI-W00 时，证据直接进入平板证据库，在平板本机完成识别。
- 华为分享：ALN-AL00 → MRO-W00，2 份材料存入平板证据库，并在平板完成识别和分类。
- 引导式演示：五步全部真实调用跑通，其中一次总用时约 8 分 35 秒（含等待模型）。

**隐私**
- 应用不需要项目自建服务器。
- 对话、证据、报告只保存在本机沙箱。

**尚未验证或有限制的项目**
- 兼容 API 23 的低版本设备只做了编译，没有真机验证。
- 平板竖屏、平板深色模式下的分栏、分屏和悬浮窗等多窗口模式。
- 新用户首次打开时自动弹出欢迎页。
- 碰一碰「按碰的位置决定材料去向」尚未实现。
- 内置模型为 deepseek-v4-flash。待确认：比赛时是否允许或需要说明使用的第三方模型。

## 8. 演示建议

- 用「我的 → 新手引导 → 演示模式 → 开始演示」走完张三的五步故事，约 5 分钟（不含等待模型），调用模型 4 次。
- 现场网络差时，步骤卡在 5 秒后提供备用结果。没有时间走完五步时，用「直接查看示例结果」。
- 平板加分环节：横屏分栏；在支持的设备组合上，手机碰平板发送证据。
